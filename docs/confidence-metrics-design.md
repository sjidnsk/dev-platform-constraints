# 开发环境-平台-约束模型与可信度指标设计

> 整理来源：Notion 页面“月面巡视探索”及其关联的研究构想笔记、研究报告、研究图谱、文献补充版。
> 整理日期：2026-05-26。
> 用途：为 `dev-platform-constraints` 子项目定义建模范围、核心数据层、可信度指标和后续开发接口。

## 1. 问题定位

“环境-平台-约束模型与可信度”是整个月面巡视探索框架的底座。它回答三个基础问题：

1. 月面环境状态如何表达。
2. 平台能力如何转化为可计算约束。
3. 地图和环境判断的可靠性如何量化，并进入探索和路径规划。

该模块不直接追求完整自主探索闭环，而是为后续模块提供统一状态表达：

```text
建模认知 -> 探索决策 -> 路径执行 -> 观测反馈
```

其中本子项目主要负责第一环节，并为探索目标选择和全局/局部路径规划输出可用的地图层、约束层和可信度层。

## 2. 总体状态模型

建议将时刻 `t` 的系统状态表示为：

```text
S_t = { M_t, P, C_t, B_t }
```

| 符号 | 含义 | 说明 |
| --- | --- | --- |
| `M_t` | 多层环境地图 | 高程、坡度、障碍、崎岖度、光照、通行性、通行代价、可信度、价值和有效性等通道 |
| `P` | 平台能力参数 | 车辆几何、运动学、能耗、传感器范围等相对稳定参数 |
| `C_t` | 约束集合 | 任务约束、能力约束、安全约束、信息约束 |
| `B_t` | 环境可信度/不确定性描述 | 可信度分量、数据来源、更新时间、分辨率和观测质量等元数据 |

`M_t` 和 `B_t` 会随观测更新；`P` 通常是设计参数或标定参数；`C_t` 既包含固定阈值，也包含随任务、光照、地图更新变化的动态约束。

`M_t` 中的 `confidence` 是给规划器使用的派生层；`B_t` 是生成该层所需的完整不确定性状态。这样可以避免把一个 0 到 1 的综合可信度数值误当作所有不确定性信息。

工程实现需统一以下约定：

- 长度单位使用米，角度单位使用度，时间单位使用秒或仿真步，并在配置中显式声明。
- 所有栅格层必须共享坐标系、分辨率和边界；跨来源地图进入融合前必须完成配准或重采样。
- 每个栅格层应携带 `source_id`、`timestamp`、`resolution`、`frame_id` 和 `valid_mask` 元数据。
- `NaN` 或无效值表示未知/不可用数据，不能与低可信度混用；低可信度表示数据存在但可靠性不足。
- `confidence` 表示信息可靠程度，不等同于“可通行概率”；通行性和通行代价应由约束与代价模型另行计算。

## 3. 多层环境地图

环境不应只建成单一障碍栅格，而应建成面向规划的多通道动态地图。

| 地图通道 | 建议变量名 | 作用 |
| --- | --- | --- |
| 高程 | `elevation` | 地形基础输入，可由 DEM、仿真地形或局部重建得到 |
| 坡度 | `slope` | 由高程梯度派生，直接影响爬坡可行性和能耗 |
| 崎岖度 | `roughness` | 可由局部高程方差、法向变化或粗糙度指标计算 |
| 障碍概率 | `obstacle` | 表示石块、坑、断坎、不可通行区域的存在概率或二值判断 |
| 障碍高度 | `obstacle_height` | 表示障碍物或断坎的近似高度，用于和平台越障能力比较 |
| 光照 | `illumination` | 表示太阳可见比例、阴影、能源可用性；后续可扩展为时变层 |
| 通行性 | `traversability` | 融合环境和平台能力后的可通行评分或概率，取值越高越容易通行 |
| 通行代价 | `cost` | 给规划器使用的非负代价，取值越低越适合通行 |
| 可信度 | `confidence` | 表示当前环境信息判断是否可靠 |
| 任务价值 | `value` | 表示科学价值、采样价值、必须巡视区域或人工指定目标 |
| 有效性 | `valid_mask` | 表示该栅格是否具备足够输入数据参与约束和代价计算 |

最小开发版本可以先实现二维或 2.5D 栅格地图：

```text
GridMap {
  resolution
  origin
  width
  height
  frame_id
  layers: elevation, slope, roughness, obstacle, obstacle_height, illumination,
          confidence, value, traversability, cost, valid_mask
  metadata: source_id, timestamp, layer_resolution, layer_validity
}
```

## 4. 平台能力模型

平台能力是把月面环境转化为约束和代价的关键。初版建议至少包含：

| 参数 | 建议变量名 | 用途 |
| --- | --- | --- |
| 最大爬坡角 | `max_slope_deg` | 判断坡度硬约束或坡度代价 |
| 最大越障高度 | `max_obstacle_height` | 判断石块、断坎、托底风险 |
| 底盘离地间隙 | `ground_clearance` | 约束障碍跨越能力 |
| 最小转弯半径 | `min_turning_radius` | 支撑 Hybrid A* 或局部轨迹曲率约束 |
| 轮距/轴距/轮径 | `track_width`, `wheel_base`, `wheel_radius` | 支撑车辆几何与运动学约束 |
| 速度范围 | `speed_min`, `speed_max` | 支撑执行时间和能耗估计 |
| 感知距离 | `sensor_range` | 判断可观测区域和可信度更新范围 |
| 视场角 | `sensor_fov` | 判断观测覆盖、下一视点选择 |
| 能耗参数 | `energy_model` | 支撑路径代价和任务约束 |

平台能力通常不是可信度指标的主体。可信度重点应放在环境信息是否可靠；平台能力更多作为已知先验、标定参数或仿真参数进入约束模型。

平台参数配置应区分三类来源：公开资料直接给出的参数、由公开资料近似得到的参数、仅用于仿真的假设参数。`min_turning_radius`、`sensor_range` 和 `sensor_fov` 若缺少可靠公开值，不应硬编码为事实值；初版可给出可调默认值，并在配置中标记为 `assumed`。如果 P0 阶段只使用普通栅格 A*，可先不启用转弯半径约束；当切换到 Hybrid A* 或局部轨迹生成时，再强制检查曲率和最小转弯半径。

## 5. 约束分类

约束建议同时按来源和强度组织。

### 5.1 按来源分类

| 约束类型 | 内容 |
| --- | --- |
| 任务约束 | 高价值区域、采样点、必须观测区域、禁入区域、时间窗口 |
| 能力约束 | 最大坡度、越障高度、转弯半径、速度、能耗 |
| 安全约束 | 碰撞、坑洼、阴影、通信不可达、地图无效、低可信且高风险区域 |
| 信息约束 | 未知区域、低可信区域、观测收益、地图更新收益 |

### 5.2 按强度分类

| 强度 | 说明 | 示例 |
| --- | --- | --- |
| 硬约束 | 违反后不可通行或任务不可接受 | 碰撞、超过最大坡度、越障高度超限、禁入区、地图无效、曲率超限 |
| 软约束 | 可通过代价函数惩罚或奖励调节 | 路径长度、崎岖度、能耗、低可信度、偏离高价值区域 |

低可信度本身不应被简单等价为不可通行。更合理的处理是根据风险和任务价值分情况进入代价或探索目标选择。只有当低可信度叠加高坡度、高障碍概率、阴影风险或关键数据缺失时，才应升级为强惩罚或硬约束。

## 6. 可信度指标定义

可信度定义为：多源信息对某个位置或区域环境状态判断的可靠程度。

对每个栅格或局部区域 `x`，定义：

```text
c(x, t) ∈ [0, 1]
```

其中：

- `c = 1` 表示环境判断高度可信。
- `c = 0` 表示已有环境判断极不可靠；数据不可用应通过 `valid_mask = false` 表示。
- `u(x, t) = 1 - c(x, t)` 可作为不确定性指标。

可信度服务两个目标：

1. 规划避险：低可信且高风险区域不应被当作普通可通行区域。
2. 主动探索：低可信但潜在高价值区域可以成为观测目标。

## 7. 可信度分量

建议将综合可信度拆成以下分量。

| 分量 | 建议变量名 | 含义 | 典型影响因素 |
| --- | --- | --- | --- |
| 分辨率可信度 | `c_resolution` | 地图分辨率是否满足当前规划尺度 | 轨道 DEM、局部重建分辨率、栅格尺寸 |
| 观测覆盖可信度 | `c_observation` | 该区域是否被传感器有效观测 | 观测距离、视场角、遮挡、传感器质量 |
| 时间新鲜度 | `c_recency` | 观测是否足够新 | 上次观测时间、地图更新时间、时间衰减 |
| 多源一致性 | `c_consistency` | 不同来源是否给出一致判断 | 轨道高程、车载视觉、激光/双目重建、局部点云 |
| 模型置信度 | `c_model` | 学习模型或通行性模型输出是否稳定 | 方差、熵、置信区间、预测分歧 |
| 几何/光照质量 | `c_geometry` | 观测几何和光照条件是否利于判断 | 低太阳高度角、阴影、斜视角、强遮挡 |

最小版本可先实现前五项；`c_geometry` 可在光照或视觉质量建模较成熟后加入。

## 8. 综合可信度融合

初版可采用加权融合：

```text
c(x, t) = clamp(
  w_r c_resolution
  + w_o c_observation
  + w_t c_recency
  + w_s c_consistency
  + w_m c_model,
  0, 1
)
```

其中权重满足：

```text
w_r + w_o + w_t + w_s + w_m = 1
```

若部分分量缺失，应只在有效分量上重新归一化：

```text
c(x, t) = sum(w_i c_i valid_i) / sum(w_i valid_i)
```

若 `sum(w_i valid_i) = 0`，该栅格不应被默认视为低可信可通行，而应标记为 `valid_mask = false`，由约束层按地图无效处理。尚未实现的分量应令 `valid_i = 0`，不应把缺失分量当作 0 分参与融合。

建议默认权重从可解释性出发：

| 分量 | 初始权重建议 |
| --- | --- |
| `c_resolution` | 0.20 |
| `c_observation` | 0.30 |
| `c_recency` | 0.15 |
| `c_consistency` | 0.20 |
| `c_model` | 0.15 |

这些权重不是最终结论，应作为配置项，在实验中做消融分析。

## 9. 可信度更新逻辑

可信度地图应随观测滚动更新。

### 9.1 初始化

轨道先验地图可用于初始化：

```text
c_initial(x) = c_resolution_orbital(x)
```

如果只有粗分辨率 DEM，则全局可用但局部可信度不应过高。文献补充中提到轨道地图与车载局部地图存在尺度差异，这正是可信度设计的重要动机。

### 9.2 观测更新

平台获得新观测后，在传感器可见区域内提升 `c_observation` 和 `c_recency`：

```text
c_observation(x, t+) = observation_quality(x, pose_t, sensor)
c_recency(x, t+) = 1
```

观测质量可由距离、入射角、遮挡和传感器噪声共同决定。初版更新时不宜无条件覆盖已有可信度：若新观测质量高于旧观测，可用加权平均或取较高质量观测；若新观测与先验冲突，则应同时降低 `c_consistency`，而不是只提高综合 `confidence`。

### 9.3 时间衰减

未被重新观测的区域应随时间衰减：

```text
c_recency(x, t) = exp(-Δt / τ)
```

`τ` 是时间常数，可按仿真步长或任务时间尺度设置。

### 9.4 多源一致性

当轨道先验与局部观测差异较大时，应降低一致性可信度：

```text
c_consistency(x) = exp(-error(x)^2 / σ^2)
```

其中 `error(x)` 可以是高程差、坡度差、障碍概率差或通行性预测差。

### 9.5 P1 贝叶斯更新边界

P1 阶段引入贝叶斯更新时，应先明确被更新的状态变量。例如可以更新 `p_obstacle(x)`、`p_traversable(x)` 或某个离散地形状态，而不是直接对综合 `confidence` 做不可解释的概率更新。

推荐形式为：

```text
posterior_state(x) ∝ likelihood(observation | state) * prior_state(x)
```

贝叶斯更新输出的是环境状态后验分布；`confidence` 可以由后验熵、方差、置信区间宽度或观测一致性派生。这样能保留“状态估计”和“估计可信度”之间的区别。

## 10. 可信度进入通行代价

综合通行代价应定义为边或局部运动片段的非负代价，而不是单纯的栅格属性。栅格代价可作为边代价的一部分：

```text
J(x_i, x_j) =
  k_d step_length(x_i, x_j)
  + k_s slope_cost(x_j)
  + k_r roughness_cost(x_j)
  + k_o obstacle_cost(x_j)
  + k_l illumination_cost(x_j)
  + k_c confidence_risk(x_j)
  - k_v bounded_value_reward(x_j)
```

其中可信度风险项建议采用：

```text
confidence_risk(x) = (1 - c(x)) * base_risk(x)
```

`base_risk(x)` 可由坡度、障碍、崎岖度、阴影等风险合成。这样可以区分三种情况：

| 情况 | 处理策略 |
| --- | --- |
| 低可信且高风险 | 提高路径代价，必要时设为禁行 |
| 低可信但高价值 | 作为优先观测目标，而不是直接穿越 |
| 高可信且低风险 | 作为候选通道 |

`bounded_value_reward` 必须有上限，且最终边代价应保持非负，避免路径规划中出现负代价或为了“刷价值”而绕行。若 `value` 表示科学观测收益而非通行收益，默认应只进入探索目标效用；只有在明确需要偏向高价值区域巡检时，才以较小权重进入通行代价。

实现时建议对最终边代价做下限保护：

```text
cost_edge(x_i, x_j) = max(min_edge_cost, J(x_i, x_j))
```

## 11. 可信度进入探索效用

探索目标选择不应只看未知边界，也应考虑低可信区域、高价值区域、路径瓶颈和规划可达性。各项效用进入求和前应归一化或限幅，否则视场面积、路径长度或价值图尺度会主导结果。

候选目标 `g` 的效用可写为：

```text
U(g) =
  α I(g)
  + β V(g)
  + ρ ΔC(g)
  - γ R(g)
  - λ L(g)
  - η E(g)
```

| 项 | 含义 |
| --- | --- |
| `I(g)` | 信息增益或未知区域覆盖 |
| `V(g)` | 科学价值或任务价值 |
| `ΔC(g)` | 预计可信度提升 |
| `R(g)` | 地形、光照、低可信度综合风险 |
| `L(g)` | 路径长度、时间或重规划代价 |
| `E(g)` | 能耗代价 |

其中：

```text
ΔC(g) = sum_x max(0, c_after(x | observe g) - c_before(x))
```

实际排序中可使用平均提升或面积归一化版本：

```text
ΔC_norm(g) = ΔC(g) / max(visible_area(g), ε)
```

全局规划应为探索目标提供可达性和路径代价反馈。若某个目标信息增益高，但绕行代价过大或需要穿越低可信高风险区域，应降低其效用。

## 12. 初版开发接口建议

建议把本子项目拆成以下可测试模块。

| 模块 | 职责 | 主要输入 | 主要输出 |
| --- | --- | --- | --- |
| `data_contracts` | 管理单位、坐标系、元数据、有效性和层命名约定 | 地图层、配置文件 | 数据校验结果、统一元数据 |
| `map_layers` | 管理多层栅格地图 | DEM、障碍、光照、价值 | 统一 `GridMap` |
| `terrain_features` | 派生坡度和崎岖度 | `elevation` | `slope`, `roughness` |
| `platform_model` | 管理平台能力参数 | 配置文件 | 平台约束对象 |
| `constraints` | 生成硬约束和软约束 | 地图层、平台参数、任务参数 | 可通行掩膜、代价分量 |
| `observation_model` | 计算传感器可见区域和观测质量 | 位姿、传感器参数、地形遮挡 | 观测掩膜、观测质量层 |
| `confidence` | 计算和更新可信度 | 分辨率、观测、时间、多源误差 | `confidence` 层 |
| `costmap` | 融合综合通行代价 | 地图层、约束、可信度、价值 | `traversability` 和 `cost` 层 |

## 13. 任务开发清单

任务开发建议按“基础表达先行、约束闭环优先、可信度逐步增强”的顺序推进。每项任务都应形成可运行代码、最小样例和对应验证结果。

### 13.1 P0：基础数据结构

- [ ] 定义 `GridMap` 数据结构，支持 `resolution`、`origin`、`width`、`height` 和多层栅格读写。
- [ ] 约定核心层命名：`elevation`、`slope`、`roughness`、`obstacle`、`obstacle_height`、`illumination`、`confidence`、`value`、`traversability`、`cost` 和 `valid_mask`。
- [ ] 实现地图层合法性检查，包括尺寸一致性、坐标系一致性、单位声明、空值处理、数值范围和缺失层提示。
- [ ] 为每个输入层记录 `source_id`、`timestamp`、`resolution`、`frame_id` 和有效性元数据。
- [ ] 准备最小示例数据，至少包含一张 2D 或 2.5D 高程图及对应障碍、光照、价值初始层。

### 13.2 P0：地形特征派生

- [ ] 基于 `elevation` 派生 `slope`，明确坡度单位、边界处理和异常值处理策略。
- [ ] 基于局部窗口派生 `roughness`，支持窗口尺寸配置和归一化输出。
- [ ] 建立地形特征单元测试，覆盖平面、斜坡、突变断坎和缺失数据场景。

### 13.3 P0：平台能力与硬约束

- [ ] 定义平台参数配置文件，包含 `max_slope_deg`、`max_obstacle_height`、`ground_clearance`、`min_turning_radius`、`sensor_range`、`sensor_fov`、能耗参数占位和参数来源标记。
- [ ] 提供“玉兔/玉兔二号”近似默认配置，并将缺少可靠公开值的字段标记为 `assumed`。
- [ ] 实现 `platform_model` 参数加载、默认值校验和越界提示。
- [ ] 实现 `constraints` 模块的硬约束掩膜生成，至少覆盖坡度、障碍和禁行区域。
- [ ] 输出硬约束触发原因层，便于调试某个栅格为何不可通行。

### 13.4 P1：可信度指标计算

- [ ] 实现 `c_resolution`，根据地图分辨率和规划尺度给出分辨率可信度。
- [ ] 实现 `c_observation`，根据传感器距离、视场角和遮挡占位逻辑计算观测覆盖可信度。
- [ ] 实现最小 `observation_model`，输出传感器可见区域和观测质量层。
- [ ] 实现 `c_recency`，支持按时间步或任务时间进行指数衰减。
- [ ] 实现 `c_consistency`，支持轨道先验与局部观测之间的高程、坡度或障碍差异度量。
- [ ] 预留 `c_model` 接口，用于后续接入通行性模型方差、熵或置信区间。
- [ ] 明确缺失分量的 `valid_i` 处理规则，避免缺失数据被误算为低可信。

### 13.5 P1：综合可信度融合与更新

- [ ] 实现加权融合公式，并支持缺失分量时按有效分量重新归一化。
- [ ] 将融合权重放入配置文件，记录默认权重和实验覆盖范围。
- [ ] 实现局部观测更新接口，在传感器可见区域内更新 `c_observation`、`c_recency` 和综合 `confidence`。
- [ ] 提供更新前后差异输出，包括平均可信度、低可信区域面积和 `ΔC`。
- [ ] P1 增加贝叶斯更新接口，先更新明确的环境状态后验，再由后验不确定性派生可信度。

### 13.6 P1：通行代价与路径验证

- [ ] 实现 `costmap` 融合，至少包含步长、坡度、崎岖度、障碍、光照、可信度风险和受限价值奖励项。
- [ ] 实现 `confidence_risk = (1 - c) * base_risk`，避免把低可信区域简单等同为不可通行。
- [ ] 保证规划边代价非负；如果价值只表示科学收益，默认只进入探索效用，不进入通行代价。
- [ ] 接入 A* 或等价全局规划器，验证给定起终点是否可达。
- [ ] 输出路径长度、综合代价、硬约束违反数和低可信高风险穿越比例。

### 13.7 P2：探索效用与任务目标

- [ ] 实现候选目标 `g` 的效用计算，包含 `I(g)`、`V(g)`、`ΔC(g)`、`R(g)`、`L(g)` 和 `E(g)`。
- [ ] 对效用各项进行归一化或限幅，避免可见面积、价值尺度或路径长度单项主导目标排序。
- [ ] 建立低可信高价值区域的目标选择样例，验证其优先观测而不是直接穿越。
- [ ] 将全局规划反馈的路径代价和可达性纳入目标排序。

### 13.8 P2：实验与文档交付

- [ ] 固化最小闭环脚本：生成地图、派生特征、生成约束、融合代价、规划路径、模拟观测、更新可信度。
- [ ] 增加可视化输出，至少展示 `elevation`、`slope`、`confidence`、`costmap` 和规划路径。
- [ ] 增加数据契约检查报告，展示输入层来源、单位、分辨率、有效区域和缺失层。
- [ ] 形成验证报告模板，记录输入配置、指标结果、失败案例和下一步参数调整。
- [ ] 维护接口说明，确保后续探索决策和路径规划模块可以稳定消费地图层、约束层和可信度层。

## 14. 最小可验证版本

建议优先完成以下闭环，而不是一开始实现复杂局部优化：

该闭环对应 P0 基础能力加 P1 中最小可信度和代价更新能力，不等同于只完成 P0 任务。

1. 构造二维或 2.5D 月面高程图。
2. 生成坡度、崎岖度、障碍、障碍高度、光照、价值、可信度和有效性通道。
3. 根据平台参数生成硬约束掩膜。
4. 根据综合代价函数生成非负 `cost` 层和可解释的 `traversability` 层。
5. 用 A* 验证给定目标是否可规划。
6. 模拟一次局部观测，更新可信度。
7. 比较更新前后的代价图和路径变化。

## 15. 验证指标

开发阶段建议先使用可量化指标验证模型有效性。

| 类别 | 指标 |
| --- | --- |
| 可信度质量 | 平均可信度、低可信区域面积、观测后可信度提升、时间衰减曲线 |
| 安全性 | 碰撞次数、最大坡度违反次数、低可信高风险区域穿越比例 |
| 规划质量 | 路径长度、综合代价、能耗估计、重规划次数 |
| 探索效率 | 未知区域覆盖率、信息增益、可信度提升、高价值区域覆盖率 |
| 约束一致性 | 硬约束违反数、平台能力阈值触发是否正确 |
| 数据契约 | 坐标系一致性、单位一致性、有效栅格比例、缺失层数量、无效值处理正确率 |
| 数值稳定性 | 代价非负率、归一化后指标范围、缺失可信度分量处理、极端场景下是否可解释失败 |

## 16. 待明确问题与当前决策

以下问题已按初版开发目标形成当前决策。后续如获得更精确的平台、载荷或任务约束数据，可再替换配置参数。

1. 平台参数：按已有中国月球车/巡视器公开参数近似，初版以“玉兔/玉兔二号”级别轮式巡视器为基准。建议采用约 `1.5 m x 1.0-1.1 m x 1.0-1.1 m` 车体尺度、约 `136-140 kg` 质量、六轮移动构型、`max_slope_deg = 20`、`max_obstacle_height = 0.20 m`、最高移动速度约 `200 m/h` 作为默认近似。`min_turning_radius`、`sensor_range` 和 `sensor_fov` 保留为可配置项，因为公开资料难以稳定给出统一数值。配置文件应给每个字段标记 `public`、`estimated` 或 `assumed`。
2. 地图来源：轨道 DEM 作为全局先验地图，用于大尺度地形背景、初始高程层和全局规划边界；仿真地形用于开发调试、参数消融和极端场景测试；局部视觉/激光重建作为近场高分辨率更新源，主要修正障碍、坡度、崎岖度和可信度层。
3. 光照建模：采用两阶段方案。初版使用静态 `illumination` 栅格层参与能源可用性、安全风险和通行代价计算；数据结构和接口预留时间维度，后续扩展为离散时间片 `illumination(x, t)`，支持随任务时间变化的阴影和太阳可见性。
4. 可信度融合：初版采用可解释的加权融合，确保各可信度分量可配置、可消融；P1 阶段增加贝叶斯更新，用新观测逐步修正环境状态或可信度估计。暂不规划高斯过程和概率地形状态图，避免初期模型复杂度过高。
5. 价值图来源：采用分阶段方案。初版 `value` 层由人工配置或手工标注生成，用于验证代价函数和探索效用；P1 阶段增加规则推断，例如综合地形可达性、光照条件、未知度、低可信高收益区域等因素；后续再对接科学目标模型。
6. 约束阈值：直接禁行条件包括超过最大坡度、明确障碍/断坎、禁入区域、地图无效或缺失、平台几何无法通过的区域。代价惩罚条件包括接近坡度上限、崎岖度偏高、低光照、低可信但非高风险区域、绕行成本高、偏离高价值目标。低可信且基础风险高的区域作为条件禁行或强惩罚处理，例如低可信叠加高坡度、高障碍概率或阴影风险时，可从惩罚升级为禁行。
